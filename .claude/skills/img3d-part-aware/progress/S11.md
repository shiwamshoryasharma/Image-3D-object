# S11 Workflows: compiler, service, store, API (2026-10-22)
## Built
- `services/workflow_compiler.py`: `WorkflowCompiler(features=, jobs=, references=)`, `compile(graph) -> CompileResult(valid, issues, request, mode, node_ids)`, `graph_from_request(simple)` (simple form ≡ graph form). Checks run in phases and stop at the first phase with an error: limits → structure (unknown type/port, type mismatch, port already connected, too many instances, locked, Kahn cycle) → sources → wiring (missing input, unsupported topology) → per node (availability from `/features`, params, existence) → workflows flag (workflow mode only). `no_sink` is a warning and adds an implicit export. `mode == "job"` for input_image → image_to_3d (→ export).
- `services/workflow_service.py`: the `WORKFLOW_STEPS` table (§4.7.3 rows `WorkflowStepDef(id, node, weight, create_child)`).
  - Create is all-or-nothing: 404 source, 422 empty set / foreign primary, 409 unfinished job, 503 flags and capabilities (prompt / image_to_3d / segmentation profile / part strategy), 422 `unsupported_by_engine`, 429 run queue or job queue. If the first child is refused, the record is removed and the refusal is returned.
  - `advance` is idempotent (per-workflow lock): it maps child state onto steps (progress, `warning_count`, artifacts, outputs), imports candidate 0 (`auto_first`) and creates the next child. A failure gives `step_failed` with `child_error` copied from the child; a refused child creation gives `queue_full` / `step_failed` with `child_id: null`.
  - Advance is triggered by a bus subscription (4 child event types, filtered by the active-children index), a sweep every `workflow_sweep_interval_s` and startup.
  - Cancel cancels the active child; delete gives 409 while active and keeps the children; `ig_` delete guard (S4's request).
- `storage/workflow_store.py`: frozen §7.2 API plus get/list/save(durable)/graph files/discard. Thread-safe in-memory index with a cached `active_child_ids` / `workflow_for_child`; `recover_interrupted` marks queued/running workflows failed `interrupted`.
- `api/v1/workflows.py`: every §6.5 route (catalog `ETag` + 304, validate, create, list with filters, get, graph, cancel, delete).
- New test-only script `test/part_aware/run_workflow_smoke.py` (own test runtime `test/.runtime/s11`, refusal rules, `--parts-only JOB_ID`).

## Deviations
1. Steps: `text_to_image` is listed only for prompt sources. `segmentation`/`part_extraction` are always listed and `skipped` when not requested (as in the F11 mock). Percent counts only the requested steps.
2. When the workflow has its own `sg_`, the `pa_` is created with `workflow_id=None`. S10's `create` returns 422 for `segmentation_id` + `workflow_id`, which contradicts §4.7.1. The link is kept through `segmentation_id`, and retention protection comes from `active_child_ids`.
3. The engine precheck reads `JobService._engine`, because there is no public accessor.
4. POST with a graph: any compile error is 422 `invalid_workflow` with `details.issues` (including not_found / capability), except `graph_too_large`, which is 422 `validation_error`. The simple form uses 404/409/422/503 as designed.
5. A job source without `parts` is 422 `conflicting_fields` (`loc body.parts`); validate reports `unsupported_topology`.
6. Issue codes for malformed graphs: a duplicate node id is `too_many_instances` (`details.reason duplicate_node_id`); an edge to a missing node is `unknown_port` (`details.reason unknown_node`). Simple-form validate issues have `node_id: null`.
7. A child cancelled outside the workflow fails the workflow with `step_failed` (`child_error.code "cancelled"`; the step is `cancelled`). `stop()` does not mark workflows; the next start marks them `interrupted`, as for runs.
8. `CompileResult.node_ids` is additive.
