# F3 Workflow engine: progress report (2026-10-16)

Slice F3 (UI_DESIGN.md §11, wave A): the pure TypeScript Node engine (§4.3.1–§4.3.11). Status: **done**. Every F3
acceptance check is a unit test, so none needs a browser. Nothing imports `src/workflow/**` yet: F11's

This run resumed a stopped one. These files from the stopped run were kept, then reviewed and adjusted:
`engine/{types,registry,graph}.ts` and `nodes/{overlays,builtin,index}.ts`. `engine/plan.ts` was finished. Everything

## Built
- `engine/types.ts`: the frozen §4.3.1 types, plus some additive pieces:
  - helper types: `Point`, `Viewport`, `BypassRule`;
  - structural context types: `EngineFeatures`, `BoundFacts`, `ValidationContext`, `PartOptionsFlags` and
    `EngineInputSource`. A `FeaturesSnapshot` or `PartOptionsForm` can be passed for them as is;
  - constants: `PORT_META` (glyph, label and token per port type, §4.3.3), `CATEGORY_META`, `GRAPH_LIMITS_FALLBACK`
    (32/64/65536) and `NODE_ID_PATTERN`.
- `nodes/overlays.ts`, `nodes/builtin.ts`, `nodes/index.ts`:
  - `NODE_OVERLAYS` holds the UI-only facts (`binds`, `isSource`, `bypass`, description) for the seven user types.
    Refine, unsupported and unknown types fall back to `DEFAULT_NODE_OVERLAY` (`binds: 'none'`).
  - `BUILTIN_NODE_TYPES` is the DESIGN §4.7.2 table in `CatalogOut.node_types` shape. Only input_image, image_to_3d
    and export are available; every other type has code `legacy_backend` and reason "Needs a newer Img3D backend.".
    The refine types are locked and every hidden type keeps `hidden_by_default`.
- `engine/registry.ts`:
  - `createRegistry` throws `RegistryError` with `duplicate_type`, `port_clash` or **`refine_unlocked`** (the guard).
  - `registryFromCatalog(catalog, overlays = NODE_OVERLAYS)` reads everything else from `CatalogOut`. A type with an
    unknown category or port type is skipped, never fatal. A parts → parts node without an overlay passes its input
    through when bypassed.
  - `withNodeStates(r, features.nodes)` applies the live availability, reason and hidden flag. It can lock a node but
    never unlock one.
  - `BUILTIN_REGISTRY`.
  - `palette(...)`: categories in `NODE_CATEGORIES` order. Hidden non-refine types appear only with "Show
    unsupported". The refine group appears only with the preview flag, all its entries locked ("Paused until you
    approve refinement"). A present type is disabled ("Only one X node is supported."). An unavailable type carries
    the backend reason.
- `engine/graph.ts`:
  - `addNode` (id `n_<type>`; throws `GraphError('too_many_instances')`; locked types start bypassed), `removeNodes`,
    `connect` (replaces the link into a single-input port), `disconnect`, `setMode` (needs a bypass rule; locked and
    unknown types never become active), `moveNodes`, `setCollapsed`, `setViewport` and `setValues` (binds `none`
    only).
  - Every op is pure, returns `revision + 1` and shares untouched subtrees. A no-op returns the input doc.
  - Queries and layout: `canConnect` (ports exist, type in `accepts`, no self loop, no cycle), `topoOrder` (Kahn,
    ties by id, cycle members left out), `layeredLayout` / `tidyLayout` ("Tidy"), `edgeKey`, `nodeIdFor`.
- `engine/plan.ts`: `analyzeRun` is the one run analysis that validate, derive and compile all share. It computes:
  - the effective graph after bypass rewiring (bypassed nodes are rewired downstream first);
  - the sink: an Export that has an incoming link. An Export with nothing connected is a "dangling sink";
  - the implicit-export terminal (a part set is preferred over a mesh);
  - the feeding set and the run set, parked sources and unreachable nodes;
  - the producer (image_to_3d for an image or prompt source, part_extraction for job_result);
  - `config` and `mode` (`job` iff the run is exactly {input_image, image_to_3d, export}).
- `engine/validate.ts`:
  - `validateGraph` and `validateWithAnalysis` emit the server codes with the exact §4.3.5 messages, plus the
    client-only warnings `ui_parked_source` and `ui_unreachable_node`, including the Segmentation-specific message.
  - Helpers: `structuralErrors`, `STRUCTURAL_CODES`, `firstError`, `hasErrors`, and
    `mergeIssues(client, serverIssues)` / `fromServerIssue`. The merge puts server issues first and lets them win the
    dedupe on `(code, nodeId, port)`; it is ready for `useWorkflowValidation`.
- `engine/template.ts`: `templateFromConfig(c, r, revision = 0)` uses the deterministic §4.3.6 layout, with the
  other source parked. It also provides `TEMPLATE_POSITIONS`, `TEMPLATE_VIEWPORT`, `emptyDoc`, `normalizeConfig` (to
  one of the 8 valid configs) and `sameConfig`.
- `engine/derive.ts`:
  - `deriveConfig(doc, r, ctx)` returns `{config, issues}`. `config` is null only for structural errors.
  - `topologyConfig(doc, r)` gives the same config without a context.
  - `configFromStores(docSource, input, parts)`.
  - `reconcile(doc, c, r)`: the minimal edit, in this order: Part Extraction / Segmentation modes, then the source
    links, then missing nodes plus canonical links, then the template as a last resort (the viewport is kept). It
    returns `doc` itself when nothing changes and is idempotent.
  - `switchSource(doc, sourceId, r)`: the one-click "Use this source".
- `engine/compile.ts`: `compileDoc(doc, r, bound, ctx)` implements the §4.3.7 algorithm.
  - The run set only. Bypassed nodes are dropped or rewired.
  - `bound[type]` params. A stray `export` or `segmentation_id` in the part options is stripped. Future nodes use
    `def.contribute(values)`.
  - Topologically sorted nodes and edges give deterministic bytes.
  - `layout = {positions (run nodes, rounded), viewport}`.
  - The UTF-8 byte limit gives `graph_too_large`.
  - If the bound params disagree with the validation facts, compile still refuses (`invalid_param`).
  - Also exports `BoundParams`, `CompileOutput` and `utf8Length`.
- `engine/status.ts`: `projectRunState(doc, r, run, resolveUrl?)`, `legacyJobStatuses` (the §4.3.9 table),
  `baseStatus` and `RunView`.
- `engine/serialize.ts`:
  - `normalizeDoc`: tolerant reading. Invalid or duplicate ids and dangling or duplicate edges are dropped. `migrate`
    runs when the definition is newer. Unknown types are kept but bypassed. Built-ins lose their values. Layout
    coordinates are clamped to ±100000 and zoom to [0.25, 2]. Missing positions take the template slot, else the
    layered grid.
  - `loadPersistedDoc(raw)` returns one of:
    - `{kind:'ok', doc, issues}`;
    - `{kind:'empty'}`;
    - `{kind:'reset', reason:'newer_version'|'unreadable', backup}`.

    It accepts JSON text, `{doc}`, a zustand `{state:{doc}}` envelope or a bare doc.
  - `exportWorkflowFile(doc, r, appVersion)`: `{schema, version: 1, app, doc}`, never with built-in values.
  - `importWorkflowFile(text, r, limits)`: refuses files over 256 KB or over the node/edge limits. Malformed and
    newer files are refused with a message; nothing throws.
  - `fromServerGraph(graph, layout, r)` returns `{doc, issues, params}`. Params are returned per node id and never
    written into the doc.
  - `stripBoundValues`.
- `engine/index.ts` re-exports all of the above.

## Deviations from UI_DESIGN.md (with reasons)
1. **`projectRunState(doc, r, run, resolveUrl = identity)`.** The 4th parameter is optional. A pure module may not
   import `api/files.fileUrl`, so the shell passes `fileUrl`, and the engine itself only handles payload URLs (UI9).
2. **Status precedence.** Base states are ordered locked > bypassed > unavailable > idle; "Locked" says more than
   "Bypassed" on a refine node. A node outside the run's `nodeIds` keeps its base state rather than literally `idle`,
   so a bypassed node stays "Bypassed". The run lights only active, unlocked nodes. A failed step shows
   `child_error.message` when present, else `step.message`, because the child's text is more specific.
3. **Scope of `capability_unavailable` and `invalid_param`.** They are checked only for nodes in the run set; the
   §4.3.5 table says "active node". Otherwise the default template, whose parked Prompt node is active, would block
   every Run on a legacy or no-t2i backend. A parked or skipped node is never sent, so it cannot fail server-side.
4. **`unknown_node_type` severity.** An active unknown node is an error. A bypassed one, which is what an import
   produces, is a warning, since the message says "It is ignored." and it is never sent.
5. **`feature_disabled`.** Emitted only from a `ready` snapshot. LOADING/ERROR snapshots have all flags false, and the
   message "turned off" would be false there. A legacy backend instead reports `capability_unavailable`, and
   `runNodeWorkflow` toasts.
6. **`missing_required_input` scope and dangling Export.** The check covers the active nodes on the way to the end of
   the run, plus an Export with nothing connected. Such an Export is not taken as the sink, so the rest of the graph is
   not mislabelled parked or unreachable. A Segmentation node wired into Part Extraction but fed by nothing therefore
   gets "Segmentation: connect "Image"." instead of being skipped silently.
7. **`no_source`.** Also emitted when the single source has no producer in the run, for example job_result → export,
   or a prompt run without Image-to-3D. This is DESIGN's "or Part Extraction for job_result". It is suppressed when
   `unsupported_topology` (job_result + image_to_3d) already explains the problem.
8. **`deriveConfig` config.** The config is null only for structural codes (`STRUCTURAL_CODES`). `graph_too_large`,
   `capability_unavailable`, `invalid_param` and `feature_disabled` block a Run through `pipelineBlock` but keep the
   projection, so Default, Mobile and Tablet still follow the graph.
9. **Job template.** The design gives no layout for it. It is job_result (0,130) → (segmentation) → part_extraction
   → export, with no parked image or prompt sources and no Image-to-3D node. `normalizeConfig` maps the invalid
   configs (segmentation without parts, job without parts) to valid ones.
10. **Registry parameter.** `connect(doc, from, to, r?)`, `setMode(…, r)` and `setValues(…, r)` take the registry
    (multiple inputs, bypass rules, binds), and `templateFromConfig` takes an optional `revision`.
11. **Byte-limit message.** Graph plus layout over `graph_max_bytes` gives `graph_too_large` with "The workflow is too
    large (max N bytes)."; the §4.3.5 message names nodes and links only.
12. **serialize API shapes** (§4.3.10 names the behaviour, not the signatures):
    - `loadPersistedDoc` returns `ok | empty | reset{backup}`, and the store writes the backup and the template;
    - `importWorkflowFile` returns `{ok, doc, issues} | {ok:false, message, issues}`, and the caller sets the imported
      doc's revision;
    - `fromServerGraph` returns the raw params by node id. Filtering unknown param keys for "Load these settings"
      stays with F11, because the engine holds no params schemas.

    Zoom is clamped to the canvas range [0.25, 2].
13. **Additive helpers** not named in the design: `switchSource`, `topologyConfig`, `structuralErrors`, `mergeIssues`,
    `fromServerIssue`, `firstError`, `hasErrors`, `withNodeStates`, `stripBoundValues`, `analyzeRun`, `tidyLayout`
    and `utf8Length`.

## Requests to other slices
- **F11 (`store/workflowStore.ts`, `shells/node/*`):**
  - **Run index.** Node ids are deterministic (`n_<type>`), so on `removeNodes` the store must drop the removed ids
    from every `runIndex` entry. Otherwise a node deleted and re-added after a Run would inherit that run's state.
  - **Registry.** Build it as `withNodeStates(catalog ? registryFromCatalog(catalog) : BUILTIN_REGISTRY,
    features.nodes)` and catch a `RegistryError` from `registryFromCatalog` (fall back to `BUILTIN_REGISTRY`).
  - **Loading and importing.** On `kind:'reset'`, write `backup` to `img3d.workflow.backup` and show
    `SERIALIZE_MESSAGES.restored`. Give an imported doc the revision `current + 1`.
  - **Status.** Pass `fileUrl` as `projectRunState`'s `resolveUrl`.
  - **Validation.** Use `mergeIssues` / `firstError` in `useWorkflowValidation` and for `pipelineBlock`.
  - **"Load these settings".** Filter unknown param keys before writing them to the stores.
- **F11 / F5:** on a legacy backend, pass the *effective* (forced-off) `parts.enabled` to `configFromStores`.
  Otherwise a stored `parts.enabled = true` would reconcile Part Extraction to active, and the Node Run would be
  blocked by `capability_unavailable` (UI11 already forces parts off for the other modes).
