## Deviations from UI_DESIGN.md (with reasons)
1. **Form and preference types live in the pure libs.** `InputSource`, `PromptFlow`, `PromptForm` and
   `PartOptionsForm` are in `lib/forms.ts`. `Preferences`, `DensityPreference`, `MotionPreference`,
   `NodeViewPreference` and `LinkStyle` are in `lib/uiModes.ts`. §3.1 and §3.3 show them in the store files. The
   pure sanitizers need these types, and pure modules cannot import stores. The F5 stores should import and
   re-export them.
2. **`ERROR_FEATURES` is exported.** It is a snapshot with status `error`, code `error` and reason "Could not read
   backend features. Retrying…". §2.5 describes it as "LOADING_FEATURES with code 'error'". The `error` status is
   what rules 5b and `features_error` check.
3. **`normalizeFeatures` tolerance.**
   - An unavailable entry that has a code but no reason gets the reason `Not available (<code>).`.
   - An entry without a boolean `available` becomes `{available:false, code:'missing'}` with the reason "The backend
     did not report this capability.".
   - Model entries that lack their core fields are skipped.
4. **`AvailabilityInputs`** is designed here, since §2.10 leaves the input shape open. `nodeShellActive` means
   `navigationStore.runOverride !== null`. `submitting` means the job store or the run store is submitting.
5. **Notes.**
   - For prompt plans the cold-start note takes precedence over the 3D engine and queue notes.
   - When `cold_start_s` is missing, the note reads "The text-to-image model loads first.".
   - A blocked plan, which only happens with the Node shell, counts as a 3D plan for the job-queue rule.
6. **Mobile posture typing guard.** The §4.5.1 rule 1 typing guard also applies to `nextMobilePosture`, so the soft
   keyboard never flips the phone layout. §3.5 lists the guard only for the tablet posture.
7. **`partsModel` additions (additive only).**
   - `PartView` gains `expected` and `geometry {status, openBoundaryLoops, watertight}`, which the §6.5 inspector
     facts need.
   - `PartSetView` gains `hasManifest` (for "Details unavailable") and `missingExpected`.
   - `displayStates` takes `PartSelection`, which is structurally `Pick<PartViewState, 'hidden' | 'isolated' |
     'selected' | 'hovered'>`. `partStore` does not exist yet, and a pure module must not depend on it.
   - `displayStates` semantics, in order:
     - `hidden` = hidden by the user;
     - `dimmed` = outside the isolated part (the viewer does not draw it; the list greys the row);
     - `selected`;
     - `highlighted` = hovered.
   - `partColorIndex` returns 0 for an id that is not in the set.
   - The cap is `MAX_PARTS = 512`, with a `parts_truncated` warning.
   - Unknown kinds produce an `unknown_part_kind` warning.
   - Manifest warnings come first. Run warnings with other codes are appended once.
   - A base record that names itself as its `parent` gets `parentId: null`.
8. **`runSteps` API.** §2.4 fixes only `isStaleRun`; the rest of the API is designed here. `isStaleRun` follows
   `jobStore.isStale` exactly: a terminal record accepts only the same status, and unknown timestamps are accepted.
9. **`errorText` shape.**
   - The context is `{subject?: RunLabelKind | 'candidate', label?}`.
   - Run errors without a fixed text read `${label}: ${message}`. `label` defaults to "Generation", and unknown future
     codes use the same form.
   - A 422 prompt error shows the backend `msg` inline.
   - `unsupported_by_*` texts read `ctx.allowed` from the pydantic detail item, which is what the backend sends
     (`services/generation_settings.py`). Size pairs are shown as `1024×1024`.
10. **`hasAdvancedOverrides` is now exported.** It was module-private, but the §10.2 re-export line includes it.
11. **Extra exports.**
    - `featureFlags`: `PROMPT_PRESETS`, `PROMPT_STYLES`, `SEG_SUBJECTS`.
    - `forms`: `INPUT_SOURCES`, `PROMPT_FLOWS`, `SEG_PROFILES`, `PROMPT_STORE_MAX_CHARS`, `EXTRA_TERM_MAX_CHARS`.
    - `viewport`: `ShellPostures`, `nextPostures`.
    - `uiModes`: `isUiMode`, `resolveMotion`.

    They are constants and helpers for the stores, sanitizers and App settings.
