## Deviations from UI_DESIGN.md (with reasons)
1. **`request_keys.json` additions:**
   - `paths["node.part_extraction.segmentation"] = "SegmentationOptions"`. The node's params contain a
     `segmentation` object, so the walk needs a name for it.
   - `node.{part_refine, mesh_tune, eye_correction, rig_correction, segmentation_3d, part_completion,
     part_generation}: []`. DESIGN §4.7.2 says "params model: none".

   Strict mode ignores params only for node types outside the catalog; those become `unknown_node_type` issues, not a
   schema 422.
2. **Import allowlist, meshTuner entry:** it targets `api/tunings` + `api/client`, the edges that actually violate,
   not §1.4's wording "api/blender, api/tunings". The meshTuner components import no `api/blender` values (they go
   through the store). It is still the two seeded entries.
3. **Request log:**
   - `body` is `null` for empty bodies and binary multipart uploads; `body_sha256` is kept, so no image megabytes go
     into the log.
   - `query` is an object with `token` redacted.
   - `/api/__test/*` calls are not logged.
4. **`--strict-requests off`** disables only the key check. Body rules are always on, mirroring the backend:
   - `conflicting_fields` (graph + simple form, `segmentation` without `parts`, non-null `parts.segmentation_id`);
   - `num_images` must be 1 inside workflows;
   - value ranges.
5. **`/workflows/validate` with workflows disabled** returns 200 with a `feature_disabled` issue, not a 503. The route
   creates nothing, and DESIGN §6.5 lists only 401/422 for it.
6. **Workflow steps and percent:** image and job sources have no `text_to_image` step, matching
   `workflow_failed.json`. Percent = Σ(weight × progress) over the listed steps, with done/skipped = 100 (DESIGN
   §4.7.4).
7. **Validate ordering:** structural errors (unknown type/port, type mismatch, port already connected, too many
   instances, cycle) short-circuit the semantic checks, and so do `no_source` and `multiple_sources`. `node_locked`
   and `capability_unavailable` come along with them. This order is inferred from the fixtures' server outcomes, since
   DESIGN gives none.
8. **`sg_` step labels** come from `segmentation_completed.json`, because DESIGN §4.5.5 has ids and weights only.
9. **ui_probe:**
   - Entry formats are `landmark:<role>[:<name>]`, `heading:<level>:<name>` and `button:<name>`.
   - Standalone numbers are normalised to `#`.
   - The baseline was recorded with `--seed-jobs 0` (§10.1 uses 2) so that names stay time-independent (history rows
     carry relative times).
   - `checks.oneCanvas` is `null` while no model is open.
10. **Test hooks** `--sha-file` / `--baseline` were added to `protected_frontend.mjs` / `bundle_budget.mjs`.
