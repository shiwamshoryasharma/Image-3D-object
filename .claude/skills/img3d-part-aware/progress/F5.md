**Deviations.**
1. `lib/featureFlags.ts` (F2) has no `tunerLock`/`tunerLockNotice`/`TUNER_LOCK_NOTICE`. F2 wrote it before the user
   spec alignment. It has the old `isTunerVisible(buildFlag, f)` instead. These now live in `hooks/useTunerLocked.ts`
   as `tunerLockOf`, `tunerLockNoticeOf` and `TUNER_LOCK_NOTICE`, with the §2.5 truth table.
2. `useResolvedUiMode` reads a new field, `navigationStore.readyModes` (default `{default}`), and the new action
   `setReadyModes`. Hooks cannot import `app/shellRegistry.READY_MODES` (§1.4).
3. Extra fields and functions beyond the design:
   - `inputStore.promptError` and `setPromptError`: the inline prompt error of §2.11.
   - `featuresStore.workflowsApi`: `api.workflows`, which gates `ensureCatalog`.
   - `featuresStore.loadModel`/`unloadModel` resolve to `ApiError | null`, because the store has no toast edge.
     `actions/models` toasts the error.
   - `PartSetEntry.note`: the "Some details could not be read" text.
   - Actions `adoptCandidateAsReference`, `reusePrompt`, `previewSegmentation` and `freeModelMemory`.
   - `selectPreviewSegmentation`.
4. `runStore.upsertWorkflow` only runs the adopt, parts and toast side effects (steps 2–5) for the session's
   `activeWorkflowId`. `loadIndex` stores records without side effects. Otherwise the 100 indexed workflows would
   re-adopt old jobs.
5. `useActiveRun` returns only non-terminal runs: the active workflow, then the job, then the review generation.
